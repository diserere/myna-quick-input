# Требования пользователя — Myna Quick Input

Версия: v1 (первая итерация).
Статус: согласовано с пользователем.

## 1. Цель и назначение

Расширение GNOME Shell для **быстрого голосового ввода текста** с использованием системного распознавания речи **Myna** (Ubuntu Speech-to-Text). Пользователь надиктовывает текст, и он попадает в буфер обмена — минимальное количество действий между «хочу сказать» и «текст вставлен в приложение».

## 2. Пользовательская персона

Пользователь Ubuntu GNOME (GNOME Shell 45–50), который **диктует чаще, чем печатает**. Основной поток: надиктовал → вставил из буфера обмена в нужное приложение (письмо, чат, документ). Окно ввода должно появляться по одному действию и сразу принимать фокус и диктовку — без лишних шагов и кликов.

## 3. Сценарии использования (user stories)

Каждый сценарий — с критериями приёмки. Все критерии должны выполняться.

### US-1. Открытие окна по клику на иконку

Как пользователь, я хочу, чтобы **клик по иконке микрофона** на верхней панели сразу открывал окно ввода.

Критерии приёмки:
- Клик по иконке → окно ввода открывается немедленно, без промежуточного меню.
- Фокус с самого начала находится в поле ввода (можно печатать без дополнительного клика).
- Повторный клик по иконке при уже открытом окне не создаёт второй экземпляр: фокус возвращается существующему полю, введённый текст сохраняется.

### US-2. Диктовка текста через Myna

Как пользователь, я хочу надиктовывать текст прямо в окно расширения, чтобы не переключаться между приложениями.

Критерии приёмки:
- Поле ввода — настоящий `St.Entry` с корректным фокусом (`global.stage.set_key_focus`), видимый механизмам доступности и Wayland input methods.
- При активации Myna распознанный текст вводится в поле, как при обычной печати.
- Окно остаётся открытым во время и после диктовки.

### US-3. Копирование текста в буфер и закрытие

Как пользователь, я хочу, чтобы после диктовки текст одним действием ушёл в буфер обмена, а окно закрылось.

Критерии приёмки:
- Кнопка «Копировать» копирует всё содержимое поля в буфер обмена.
- Окно сразу закрывается, фокус возвращается ранее активному окну.
- Появляется уведомление о том, что текст скопирован.

### US-4. Закрытие окна

Как пользователь, я хочу закрывать окно привычным способом — без поиска кнопки.

Критерии приёмки:
- Окно закрывается любым из трёх способов:
  1. кнопка «Закрыть» в окне;
  2. клавиша `Esc`;
  3. клик по затемнённому фону вне окна.

### US-5. Сохранение текста между открытиями

Как пользователь, я хочу, чтобы надиктованный текст не пропадал, если я случайно закрыл окно.

Критерии приёмки:
- После закрытия и повторного открытия окна (в пределах активной сессии GNOME Shell) текст остаётся в поле ввода.

### US-6. Очистка поля

Как пользователь, я хочу быстро очистить поле для следующей диктовки.

Критерии приёмки:
- Кнопка «Очистить» стирает содержимое поля.
- Фокус остаётся в поле ввода после очистки (можно диктовать сразу).

## 4. Пограничные случаи (решения по умолчанию)

Уточнены для v1; могут быть пересмотрены в следующих итерациях.

- **Повторный клик при открытом окне:** не создавать второй экземпляр; вернуть фокус существующему полю (см. US-1).
- **«Копировать» при пустом поле:** показать уведомление «Нечего копировать»; окно не закрывается.
- **Длинный текст:** поле однострочное (`St.Entry`) — ограничение v1. Многострочность — в бэклоге.
- **Недоступность Myna:** расширение открывается и работает (ручной ввод, копирование), не падает.

## 5. Нефункциональные требования

- **Совместимость:** GNOME Shell 45–50 (соответствует `metadata.json`).
- **Интеграция с Myna:** поле ввода остаётся `St.Entry` с корректным фокусом; окно размещается на стадии (`Main.uiGroup`), а не отдельным окном верхнего уровня.
- **Отзывчивость:** открытие окна — мгновенное.
- **Стабильность:** без ошибок в журнале GNOME Shell; корректная деактивация в `disable()` без «висящих» обработчиков.

## 6. Бэклог (планируемые итерации)

Пункты согласованы как цели следующих итераций; детали и критерии уточняются при планировании каждой.

- **v2 — Горячая клавиша открытия окна.** Глобальный шорткат (например, `Super+M`), открывающий окно из любой точки системы; настраиваемость.
- **v3 — Настройки расширения.** `prefs.js` + схема GSettings: настраиваемый шорткат, поведение при закрытии (сохранять/очищать текст), размер и тема окна.
- **v3+ — Многострочное поле ввода.** Замена `St.Entry` на `St.TextView` для длинных диктовок.
- **v4+ — Дополнительные способы экспорта текста.** Сохранение в файл, отправка в активное приложение и т.п.

## 7. Известные расхождения с текущей реализацией

Текущая реализация (`extension.js`) **не соответствует** требованиям; перечень — «мостик» для следующей итерации (исправление кода):

1. **UX:** клик по иконке открывает выпадающее меню с пунктом «Открыть окно голосового ввода», а не окно сразу (требуется US-1).
2. **Баг:** клик по пункту меню не открывает модальное окно — `_openQuickInputModal`/`MynaQuickInputModal` не работает в рантайме (требуется US-1).
3. **Копировать:** копирует, но не закрывает окно (требуется US-3).
4. **Сохранение текста:** при повторном открытии `_openQuickInputModal` уничтожает старое окно и создаёт новое пустое — текст теряется (требуется US-5).
5. **Esc:** клавиша `Esc` не закрывает окно (требуется US-4).
